# Wordgame Rules

Balatro-style crossword roguelike deckbuilder (working title "wordgame"). Target engine: **Godot 4 (C#, .NET 8)**.

> **Start of every session: read [`handoff.md`](handoff.md)** — current status, decisions, open concerns, next steps, and workflow tips.
> **End of every meaningful chunk of work: update `handoff.md`** (status table, decisions, next steps, HEAD/test counts, date).
> **Feature design roadmap: [`ROADMAP.md`](ROADMAP.md)** — the official plan for upcoming features (dictionaries, decks, items, Stationery, bosses, stakes, infra/simulation, game modes, presentation, persistence, build order) with *proposed* numbers. Mark entries ✅ when they land; keep current status in `handoff.md`.

## Core Principles
1. Core game logic must remain in `src/Crossword.Core` with zero game engine imports and no NuGet packages (BCL only). Enforced by `tests/Crossword.Tests/Architecture/CoreDependencyTests.cs`.
2. All state transitions must be pure and return new state instances.
3. **Determinism:** all randomness flows through the immutable `Crossword.Core.Random.Rng` (returns value + next state). Never use `System.Random`, `Guid.NewGuid`, `DateTime.Now`, or engine RNG in Core. The RNG state lives in `RunState`/`RoundState` so any run is reproducible from its seed. Each round gets its own RNG stream derived from the run RNG (`RoundRules.Start`).
4. Every new Desk Item or mechanics feature MUST include unit tests in `tests/Crossword.Tests`.

## Run Structure (implemented)
- **5 Weeks × 3 rounds:** Daily (target ×1, $3) → Saturday Stumper (×1.3, $4) → **Sunday Edition** boss (×1.6, $5 + a `BossModifier`). Week targets 510/1790/5380/14580/23920 (`RunConfig.Default`; boss-adjusted deadlines via `RunRules.TargetFor`); endless mode after victory (×2/week).
- **Bosses** (`Core/Run/BossModifiers.cs`), tiered by week via `RunConfig.BossTiers` (`BossCatalog.DefaultTiers`, ordered by measured difficulty): **Early** (Weeks 1–2) Ink Spill (6 symmetric blocked cells), Tight Margins (5×5); **Mid** (Weeks 3–4) Vowel Drought (vowels −1 chip), Tight Deadline (3 submissions), Redundant Copy (a word already formed this round — same text, main or cross — adds no letter chips; `ScoringConfig.RepeatWordsScoreZero` + `ScoreEnvironment.WordsFormed`); **Final** (Week 5) The Strict Grammarian (3+ letter words; its deadline is ×0.75 via `TargetScale`, otherwise the finale ends ~45% of runs that reach it), The Puzzle Master (two different Early/Mid bosses at once, `PuzzleMaster(First, Second, TargetScale)`; the catalog holds an unresolved template that `RunRules.BossFor` resolves from `BossCatalog.PuzzleMasterCandidates`). Endless weeks draw from every boss. Play totals are clamped at 0. The week's boss (and The Puzzle Master's pair) is picked using seed + week only (no run RNG consumed) so it can be previewed.
- **Economy:** start $4; paycheck = base + $1/unused submission + overkill ($1 per full 25% over target, cap 3) + interest ($1 per $4 held, cap 5), **topped up to at least $5** (`EconomyConfig.MinPaycheck` → `Payout.FloorTopUp`; user's choice 2026-10-10: +4.5 pts for a weak player, +0.5 at reference, so no target retune). `EconomyConfig.PerUnusedDiscard` (default 0) exists as a measured-but-rejected lever. The paycheck screen prints `Economy.HowToEarnMore(config)`. Gilded tiles pay during play.
- **Shop** (after each won round): 2 Desk Items (rarity rolled 60/30/10: Common $4 / Uncommon $6 / Rare $8, sell for half), 2 deck edits (add tile — 12% of them a **wild tile** $6 —, make a chosen tile wild 10% $5, enhance a chosen tile, strike up to 2 tiles; deck min 30), 1 **Style Guide** ($3, named per tier via `StyleGuideNames`: Pulp Paperbacks 2 → The Lexicographer's Omnibus 7+; permanently levels a word tier, +`LevelChips`/+`LevelMult`, stored in `RunState.TierUpgrades`), 1 **Stationery** ($3; Margin Clip $6 via `ShopConfig.StationeryPrices`), reroll $5 +$1 each.
- **Stationery** (`Core/Stationery/`): one-shot items in `RunState.Stationery` (2 slots, duplicates allowed, sell for half), used in-round via `RunRules.UseStationery(session, slot, lexicon, tileIds?, cell?)`. Each item declares a `StationeryTarget` (None / HandTiles / BoardTile); an item that can't take effect fails and stays in its slot. Catalog: **Answer Key** (reveals the best play; the UI places it as pending tiles), **Margin Clip** (+1 submission this round), **Scissors** (redraw up to 2 selected hand tiles without spending a discard; `RoundRules.Redraw`), **White-Out** (remove a board tile for the round; `RoundRules.RemoveTile`, UI board-targeting mode), **Red Ink Bottle** (+3 Mult on every play this round, stacks; stored as `RoundConfig.BonusMult`), **Fountain Pen** (the selected hand tile becomes wild for the round; the deck copy is unchanged). `ShopConfig.StationeryIds` (and `DeskItemIds` for Desk Items, used by balance harnesses) restricts the shop pool (null = all; the offer is rolled last so it never shifts other offers).
- **Press Runs** (`Core/Run/PressRuns.cs`, difficulty "stakes"): 8 stacking levels — 1 Proofreader (base game), 2 First Edition (Dailies pay $1 base instead of $3), 3 Late Edition (week targets ×1.05 compounding per week), 4 Rush Job (−1 submission on Sundays), 5 Ink Shortage (−1 discard), 6 Heavy Printing (rerolls start $1 higher), 7 Censored Press (one of B C F G H M P W Y per round can't be placed, not even by a wild), 8 Final Print Run (the Sunday boss becomes a `Reprint`: its rule plus one more Early/Mid boss's, none it already has). Numbers in `PressRunConfig`; tuned (user's choice: an even ladder) so the strong player (ScoreFraction 0.9) wins 55 / 44.5 / 36.5 / 23 / 18.5 / 15.5 / 13.5 / 7.5% at levels 1–8. The level lives in `RunState.PressRun`; `PressRuns.Apply(RunConfig, level)` is applied by `RunRules.NewGame(..., pressRun)` and by the save loader, so `session.Config` always holds the level's rules — **pass the base config** to `NewGame`/`PlayRun`/`Deserialize`. Mechanics: `RunConfig.BossSubmissionsDelta` (boss rounds only) / `DiscardsDelta` (every round), applied in `RoundConfigFor` *after* the boss (Tight Deadline + Rush Job = 2 submissions; min 1 / 0), `RunConfig.CensoredLetters` → `RoundConfig.CensoredLetter` (picked by `RunRules.CensoredLetterFor` from seed + round on a salted stream: no RNG consumed; `PlacementValidator`/`MoveGenerator`/`MoveRanker` take a `censoredLetter` next to `minWordLength` — every call site must pass `Config.CensoredLetter`), `RunConfig.BossExtraModifier` (in `BossFor`, separate salted stream so the base boss is unchanged and previewable). **Unlocks:** per deck — `PlayerStats.HighestPressRunWon` (deck id → level); `StatsQueries.UnlockedPressRun(stats, deck)` = highest won with that deck + 1; `StatsRules.RecordRunEnd(..., pressRun, deck)`; profiles from before Press Runs count their wins as level 1, profiles from before decks count their level for the Standard Deck.
- **Starting decks** (`Core/Run/Decks.cs`, ROADMAP §2): Standard, **The Crossword Draft Deck** (+1 Mult per intersection, deadlines ×0.7; words need 3+ letters — which bans the 2-letter cross words most intersections form, hence the deadline cut; The Strict Grammarian never appears — `RunConfig.ExcludedBosses` — so its finale is always The Puzzle Master), **The Redactor Deck** (`StartingDeck.Thin()`: 30 tiles, 12 vowels, 1 wild, incl. Q Z X J — a thin deck cycles every round, and without them it won 61%; −1 discard), **The Copy Editor's Deck** (starts with Red Pen, +1 discard, 4 Desk Item slots), **The Lexicographer's Deck** (pick an unlocked dictionary overlay at run start — see Dictionary overlays; deadlines ×0.85; 4 Desk Item slots — the acronyms alone are worth ~+2 pts to the bot and the lost slot ~−15, hence the deadline cut). Numbers in `DeckConfig`, tuned so each deck wins within a few points of Standard (see `handoff.md` §4). Like Press Runs a deck is a `RunConfig` transform: the run stores `RunState.DeckId` (and `RunState.Dictionaries`), and `RunRules.ConfigFor(base, deck, pressRun)` = `PressRuns.Apply(Decks.Apply(base, deck), pressRun)` is applied by `NewGame(..., deck)` and the save loader. Knobs: `RunConfig.MinWordLength` (max'd with the boss's in `RoundConfigFor`), `DeskSlots` (pass it to `RunState.AddDeskItem(item, slots)`; `MaxDeskSlots` = 5 is the cap), `StartingDeskItems`, `ExcludedBosses` (filtered in `BossPoolFor`, endless weeks too). **Unlocks:** every run won (any deck, any level) unlocks the next deck in `Decks.All` order (`StatsQueries.UnlockedDecks` = Standard + `RunsWon` more; nothing extra stored). Tabloid waits for a licensable Slang list (append it after Lexicographer so existing unlocks don't shift).
- **Dictionary overlays** (`Core/Lexicon/Dictionaries.cs`, ROADMAP §1): extra words legal on top of ENABLE in a run that turns them on. Catalog: **The Tech Shorthand** (`tech-shorthand`, Acronyms & Initialisms, 3+ letters: CPU, NASA, FAQ…; hand-written `Lexicon/Data/tech-shorthand.tsv`, `WORD<TAB>expansion`, ~300 entries, no brand/company/product names, no ENABLE words — tests enforce), **The Atlas Unlocked** (`atlas`, Proper Nouns & Places: OSLO, ERIE, PERU…; hand-written `Lexicon/Data/atlas.tsv`, `WORD<TAB>description`, 567 single-word place names of 3–7 letters — longer ones can't fit the 7×7 board, a test enforces — no ENABLE words, so PARIS/CHINA/TURKEY are left out; contested places get a geographic description), **The Olde English Folio** (`olde-folio`, Archaic English, a **theme dictionary**: ENABLE already has ~94% of familiar archaic words, so instead of adding words it gives +`Dictionaries.OldeFolioMult` (3) Mult per formed word on its list — THEE, HATH, ERE, YON, QUOTH… 106 words of 3–7 letters in `Lexicon/Data/olde-folio.tsv`, `WORD<TAB>gloss` — and its 5 non-ENABLE entries OER, NEER, EER, EEN, OLDE become legal). A dictionary is a theme when `DictionaryDefinition.ThemeMult` > 0 (`IsTheme`); only plain overlays must avoid ENABLE words (tests enforce). `RunRules.ConfigFor(base, deck, pressRun, dictionaries)` puts the run's theme into `RunConfig.Scoring.Theme` (`WordTheme`: name, words, Mult per word; `Dictionaries.Theme(ids)`), so hints, bots, the UI and saves (re-applied on load) all see it; the UI tags theme words in the play preview. A run's overlays live in `RunState.Dictionaries` (saved; unknown ids rejected on load); only a deck that `Decks.TakesDictionary` (Lexicographer) gets one, via `RunRules.NewGame(..., dictionary)` → `Decks.DictionariesFor` (default: the first). **The run's word graph is `LexiconLoader.For(run.Dictionaries)`** (ENABLE + overlays, built once per id set ~0.5 s and cached; no ids = `Enable`): `NewGame` starts the first round on it, and every frontend must swap its lexicon after a new run or resume (`Main._lexicon`, CLI `_lexicon`; `RunSimulator.PlayRun(..., dictionary)` does it itself). Overlay entries go through `Denylist.Default` when read. Definitions: `Dictionaries.Define(word, ids)` gives "<`SenseLabel`>. <text>" ("abbr. central processing unit", "n. capital of Norway", "arch. you (as the object of a verb)"); the UI tries the run's own dictionaries first, then WordNet, then every dictionary; the UI falls back to it after WordNet (overlay words are never ENABLE words). **Unlocks:** the first dictionary comes with The Lexicographer's Deck, then one more per run won (`StatsQueries.UnlockedDictionaries` / `WinsToUnlock`; nothing stored). New dictionaries: add a `DictionaryDefinition` (incl. its `SenseLabel`) at the end of `Dictionaries.All` (unlock order) + embedded `<id>.tsv` (csproj `LogicalName` `Crossword.Core.Lexicon.<id>.tsv`).
- **Deadlock escape:** holding Scissors (bag not empty) or White-Out (board not empty) keeps a stuck round (no legal play, no discards) alive (`StationeryCatalog.CanEscape`); `RunRules` re-checks after every transition, including using or selling Stationery (`RunRules.Recheck`), so selling the last escape item while stuck loses the round.
- **Hint:** the free in-round Hint shows a *decent* play, never the best (`Hints.Decent`, `HintConfig`: the 90th-percentile play or the best play worth ≤60% of the best score, whichever is lower). The best play costs an Answer Key. Game `--dev` adds a **Best (dev)** button next to Hint that places the best play (`Hints.Best`, the top of `MoveRanker.Rank`: highest score with the run's Desk Items, boss, theme and censored letter — not the longest word); Hint stays the decent play even in dev mode.
- **Tile enhancements:** Bold +10 Chips, Italic +2 Mult, Gilded +$1 — trigger once per formed word containing the tile, including tiles already on the board. `ScoringConfig.Describe(enhancement)` is the single source of the player-facing text (shop cards via `ShopOffer.Describe(scoring)`, tile tooltips, the deck summary, CLI `deck`/shop).
- **Wild tiles** (`Tile.IsWild`): play as any letter, chosen when placed (`Tile.As(letter)`; the UI asks with a letter picker), and score **0 letter chips** (`ScoringConfig.ValueOf(Tile)`) but count for length, tier, premiums, intersections and enhancements. Unplaced wilds carry `Tile.WildPlaceholder` — anything reading hand/deck letters must check `IsWild` (they count as neither vowel nor consonant for draws, sort last, show as "?"). The validator only lets a wild change letter. `MoveGenerator` fills a letter with a wild only when no real tile of it is left, and keeps one play per placement whatever the wild stands for (they score the same). Sources: 2 in the starting deck, shop wild tile / wild edit, Fountain Pen.
- **State:** `GameSession` (config, `RunState`, phase, current `RoundState`, `ShopState`, last `Payout`); transitions in `RunRules` / `ShopRules`; round mechanics stay in `RoundRules`.
- **Save & resume** (`Core/Save/RunSaveJson`): stores every `GameSession` field (RNG streams, bag order, board, scaling Desk Items, shop offers incl. bought `null` slots) plus the UI hand order, **except `RunConfig`** — the loader passes the current base one and applies the run's deck and Press Run (`RunRules.ConfigFor`; user's choice: a resumed run picks up new tuning; the round in progress keeps its `RoundConfig` snapshot). Reflection-based `System.Text.Json` over the records (`IgnoreReadOnlyProperties` skips computed getters); `IDeskItem`/`IStationery`/`BossModifier` are tagged by `id` (looked up via each catalog's `Find`), `ShopOffer` by kind. A save whose `version` ≠ `RunSaveJson.CurrentVersion` is rejected (no migrations yet). **Renaming or adding a state property breaks `CommittedFixture_StillLoadsIntoTheSameState`** on purpose: keep old saves loading (or bump the version), then regenerate `tests/Crossword.Tests/Save/Fixtures/run-v1.json` from `FixtureSession()` (`run-v1-before-press-runs.json` is a pre-Press-Run save that must keep loading as Proofreader, Standard Deck). An unknown `deckId` is rejected.
- **Seeded runs** (user's choice): a run on a seed the player chose (the New-run picker's seed box, or `--seed`) has `RunState.Seeded` (`RunRules.NewGame(..., seeded)`; saved, old saves load as unseeded). Play is unchanged, but its win counts in `PlayerStats.SeededRunsWon` instead of `RunsWon` and never raises `HighestPressRunWon` (`StatsRules.RecordRunEnd(..., seeded)`), so a replayable seed unlocks no deck, dictionary or Press Run.

## Game Rules (implemented)
- **Run → Rounds (blinds).** Each round: fresh board (default 7×7) with seeded, rotationally symmetric premium squares; full deck shuffled into the bag; hand of 7. **Balanced draws** (`DrawConfig`, `RunConfig.Draw` = `Balanced`): every refill stays random but guarantees ≥2 vowels and ≥2 consonants and never deals a third copy of a vowel, when the bag allows (`TileBag.DrawBalanced`; only the last slots of a refill are steered). Hand-built `RoundConfig`s (tests) default to plain draws. Starting deck (`StartingDeck`, `RunConfig.StartingTiles`): 98 lettered tiles with 41 vowels (~42%) + 2 wild tiles = 100; Y counts as a consonant.
- **Play (submission):** 1..N hand tiles in one row/column; gaps only if filled by existing tiles; must touch existing tiles (first play may go anywhere); must form ≥1 word of 2+ letters; every word formed (main + cross) must be in the lexicon; no tile may be placed as the round's censored letter (Press Run 7+). Placed tiles are consumed for the round; hand refills.
- **Discard:** costs one discard; removes chosen tiles for the round and refills.
- **Round end:** Won when Score ≥ target; Lost when submissions run out, hand and bag are both empty, or **deadlocked** (no legal play for the hand and no discards left — checked after every transition via `MoveGenerator`; held Scissors / White-Out postpone it, see Stationery).
- **Desk Items:** up to 5 slots (`RunConfig.DeskSlots`, 4 on The Copy Editor's Deck; cap `RunState.MaxDeskSlots`), no duplicates, applied left to right — slot order matters. 23 items in `Core/DeskItems/` (Starter, Conditional, Scaling, Press = Phase 2: Etymology Tome, Rubber Stamp, Printing Press Roller, Tile Rack, Coffee Stain), bought in the shop (CLI also has a dev `give` command). Items can change each round's rules as it starts via `IDeskItem.ModifyRound` (Tile Rack +1 hand size, Coffee Stain +1 blocked pair), applied in `RunRules.StartRound` after the boss, never to the deadline. Blocked pairs beyond the free squares block every free pair (no throw).
- **Lexicon:** ENABLE, words of 2–15 letters. 2-letter words are legal (lowest tier). QI/ZA are NOT in ENABLE. A run may add dictionary overlays (see Run Structure → Dictionary overlays).
- **Denylist** (`Core/Lexicon/Denylist.cs`, data `Lexicon/Data/denylist.txt`, user's choice: **slurs only**, i.e. words that target a group; profanity stays playable; a word whose main meaning is innocent — CRACKER, GUINEA, QUEER — stays): `LexiconLoader.ReadEnableWords()` drops denied words, so they are never legal, suggested or defined. Every inflection is listed explicitly (a test checks plurals and that each entry is an ENABLE word). **Every future word list (dictionary overlays) must go through `Denylist.Default.Filter`.** `ReadUnfilteredEnableWords()` is for tests and tools only. Candidate report: `dotnet run -c Release --project tools/Crossword.DefinitionsBuilder -- --denylist-candidates` (WordNet's slur/disparagement/obscenity tags → gitignored `tools/data/denylist-candidates.txt`; most are not slurs, review by hand).
- **Definitions** (UI only, no rule depends on them): `DefinitionLoader.Default.Define(word)` from embedded `Lexicon/Data/definitions.tsv.gz` — Open English WordNet 2025 (CC BY 4.0, attribution in `THIRD_PARTY_NOTICES.md`) plus hand-written `tools/Crossword.DefinitionsBuilder/supplement.txt` (function words, all 2-letter words; overrides WordNet). Inflections point at their lemma. The builder hides ethnic-slur senses, offensively tagged senses whose gloss is itself crude ("obscene terms for …", "derogatory term …"; WordNet's tags cover whole synsets, so a tag alone is too noisy) and glosses that use a denied word, then shows the next clean sense. ~62% of ENABLE is covered; the rest shows "no definition on file". Regenerate with `dotnet run -c Release --project tools/Crossword.DefinitionsBuilder` (needs `english-wordnet-2025.xml.gz` in gitignored `tools/data/`).

## Scoring Order (`ScoringEngine`, one pooled Chips × Mult per play)
1. **Tier:** longest word formed sets base Chips and base Mult (`ScoringConfig.Tiers`).
2. **Words:** each formed word adds Σ letter values (DL/TL per tile) × DW/TW — premiums only under tiles placed this play. Shared tiles count once per word, no extra bonus. Under Redundant Copy a word already formed this round adds 0. Each word's chips are kept in `ScoreContext.WordChips` (aligned with `Play.Words`; Etymology Tome reads it).
3. **Enhancements:** Bold/Italic/Gilded per formed word containing the tile.
4. **Intersections:** +`IntersectionMult` per new tile that is in both an Across and a Down word.
4b. **Theme words:** +`ScoringConfig.Theme.MultPerWord` per formed word in the run's theme dictionary (The Olde English Folio; source `theme`).
4c. **Round bonus:** +`ScoringConfig.BonusMult` (Red Ink Bottle, via `RoundConfig.EffectiveScoring`; source `bonus`).
5. **Desk Items:** `EffectPipeline` in slot order (+Chips, +Mult, ×Mult).
6. **Total:** floor(Chips × Mult). Boss modifiers may alter the `ScoringConfig` for the round (`RoundConfig.EffectiveScoring`). Every step appends an `EffectEvent` (with running totals) for UI playback.
All numbers live in `ScoringConfig` / `RoundConfig` / `PremiumPairs` / Desk Item constructor defaults — tune there, not in code.

## Balance Workflow
- `RoundSimulator` (Core/Analysis) plays rounds automatically; `skill` 1.0 = greedy best play (upper bound). Two skill models (`PlayChooser`, `SkillModel`): **Percentile** (default; 0.9 = the play better than 90% of legal plays — well below the best, since most legal plays are tiny) and **ScoreFraction** (0.9 = the best play worth ≤90% of the best score; closer to how a human plays — they find good plays, just not always the top one).
- CLI `sim [rounds]` prints per-submission score distribution, intersection rate and submissions-to-target; `hint [n]` lists best plays.
- `RunSimulator` plays whole runs; CLI `runsim [runs] [skill] [naive] [frac] [press=N] [deck=id] [dict=id]` reports victory %, week reached, unspent money, **mean submissions to win per week/day** and what killed runs (`frac` = ScoreFraction skill model; `press=N` plays at Press Run N, `deck=id` with that starting deck, `dict=id` with that dictionary overlay). Default shop bot is `EvaluatingShopBot` (`Core/Analysis/ShopBot.cs`): it records recent decisions (trimmed candidate plays) and values each purchase by re-scoring them with the resulting loadout — every slot position, replacements when full, Style Guides, scaling items projected to mid-run, money effects as reduced price. Thresholds in `ShopBotConfig`; `DeskItemGain` adds a fixed gain for items re-scoring can't value (Tile Rack's bigger hand). `NaiveShopBot` (priciest item first) kept for comparison. Stationery: the evaluating bot buys it at a fixed estimated gain per item (`ShopBotConfig.StationeryGain`, like deck edits) and `StationeryBot` uses it in rounds (Answer Key when only the best play wins the round; Margin Clip / Red Ink on a short last submission; Red Ink on a boss opener; Fountain Pen on an unused Q/Z/X/J, then Scissors; Scissors / White-Out / Fountain Pen to escape a stuck hand). The bot can also buy wild tiles/edits (`WildTileGain`/`WildEditGain`); measured no gain, so all wild gains default to 0. `SimulatedRun.StationeryUsed` lists what was used; `SimulatedRunRound.Payout` / `InRoundMoney` / `Shop` (`ShopSpend`) record every dollar.
- **Balance reference = ScoreFraction model** (`runsim 150 0.75 frac`), not the percentile bot (its 0.9 is far weaker than a human). Current numbers (150–200 runs, evaluating bot): wins ~60% / 37% / 15% at ScoreFraction 0.9 / 0.75 / 0.6; won rounds take ~2.3–2.8 submissions and 41–69% are won in 1–2. Full snapshot and history in `handoff.md` §4b–4c (decks §4, Press Runs §4a). Targets alone plateau at ~2.5 submissions per round: steeper curves turn long rounds into lost rounds (4 submissions, high per-play variance). Getting 3+ play rounds would need a structural change (e.g. 5 submissions + higher targets).
- Findings: shop decisions dominate outcomes; Pulitzer, Margin Notes and Word Count end up in >90% of skill-0.9 evaluating runs; deck edits never pay off for the bot (buying them at any estimated gain lowered win rate). Retune targets with `runsim` whenever scaling content changes.
- Current tuning rationale: tier Mult 1,1,2,2,3,3 + 3 Mult per intersection so grid-building beats isolated long words; starter items ~+35–55% alone.
- Unit tests must pin their own numbers (explicit config / constructor args) so retuning defaults never breaks them.

## Layout
- `src/Crossword.Core` — `Domain/` (state records, board, premium layout), `Rules/` (placement validation, round/draw transitions), `Scoring/`, `Effects/` (Desk Item pipeline), `DeskItems/` (concrete items + catalog), `Stationery/` (one-shot items + catalog), `Analysis/` (move generator, ranker, hints, round + run simulators), `Run/` (run config, economy, bosses, shop, `GameSession`/`RunRules`), `Lexicon/` (DAWG + embedded ENABLE, `IWordGraph` traversal, word definitions), `Save/` (run save JSON, see Save & resume), `Profile/` (player profile: `PlayerStats` incl. per-deck `HighestPressRunWon`, `StatsRules` incl. `RecordRoundWon`, `StatsQueries` incl. `UnlockedPressRun`/`UnlockedDecks`, versioned `ProfileJson` — never affects play), `Clues/` (`BoardWords.Numbered` = crossword numbering; `MarginClues.For` builds the ACROSS/DOWN margin columns: board words with definitions → lifetime records → `NewsroomClues` tips, no repeated answers), `Random/`
- `game/` — **Godot 4.7 (.NET) UI** (`Wordgame.Godot.csproj`, `project.godot`, `Scenes/Main.tscn`). UI is built in code in `Scripts/Main*.cs` + `UiKit.cs`; it only renders `GameSession` and calls `RunRules`/`ShopRules` — no rules in the UI. Visual-only state (selected/pending tiles, NEW-tile highlights, hand order) lives in `Main`. Compatibility renderer. Sidebar shows week progress (`RunProgress`); the **Style Guides drawer** (`Main.StyleGuides.cs`) slides in from the right edge over the board (Tab, the always-visible GUIDES bookmark, or the sidebar button; click outside / Esc closes; `_styleGuidesOpen` is the logical state since `Visible` lags the close slide); pending tiles can be dragged between squares or back to the hand; Desk Item ◀ ▶ tooltips preview the pending play's score after the move. Scoring playback ("ring-up") effects and all their numbers live in `Scripts/Juice.cs`; the breakdown itself prints only on submit, on the **scoring receipt** (`Scripts/Receipt.cs`): a register tape in a column right of the board that prints one line per `EffectEvent` in step with the ring-up (running chips × mult and product beside each), then a TOTAL that counts up and punches; it lingers until the player touches a tile, and a won round's shop replaces it. There is no sidebar log any more; the live preview shows chips × mult and the words only. Paper colours are `UiKit.Paper*`, the typewriter face `UiKit.Mono`. The player profile is saved by `ProfileStore` to `user://profiles/<name>.json` (Stats popup in `Main.Stats.cs`). The run is saved by `RunSaveStore` to `user://saves/<profile>.json` whenever the session changes (`Refresh` → `PersistRunIfChanged`) and on window close, and offered on launch by the **title menu** (`Main.Title.cs`, user's choice over the old straight-to-the-run auto-resume: Continue — Enter — resumes it, New run, Profile, Stats, Settings, Quit; the sidebar's Menu button reopens it; QA, dev-setup and `--seed` launches skip it; with no run `_session` is null and `Refresh` returns early). Resuming (`Main.Save.cs`) restores the stats guards so nothing is counted twice. A lost run deletes its save, a won one keeps it (endless choice). The title's New run asks for a second click while a run is in progress, then always opens the **New-run picker** (`Main.PressRuns.cs`: decks on the left, the selected deck's Press Runs on the right, an optional seed box below; clicking a Press Run starts the run; locked ones greyed; the victory screen announces deck and Press Run unlocks, or that a seeded run unlocks nothing). **Profiles** (`Main.Profiles.cs`, from the title): `ProfileStore.List` shows the profiles on disk; switching saves the current run and loads the other profile and its save; the last profile is remembered. **Settings** (`Main.Settings.cs`, `SettingsStore` → `user://settings.cfg`, game-wide): reduced motion (`Juice.ReducedMotion`: no shake, confetti, punches, stamp slam or rising text), fullscreen, text size 90–120% (`UiKit.TextScale` multiplies every font size except tile faces — use `UiKit.FontSize` for any direct font override; a change rebuilds the UI; 130%+ overflows the 1440×900 layout). The sidebar scrolls rather than growing past the window. The desk bar draws `Config.DeskSlots` slots. ## Code Conventions
- Use immutable C# `record` types for state objects; collections are `ImmutableArray`/`ImmutableList`. Note `ImmutableArray` compares by reference inside records — compare contents explicitly in tests.
- Scaling Desk Items grow via `AfterPlay`/`AfterRoundWon`, which return an updated copy (applied by `RunRules`); items needing run resources read `ScoreContext.Env` (money held, submissions left incl. current, discards left, submissions made this round, words formed this round).
- Desk Items implement `IDeskItem.Apply(ScoreContext) -> ScoreContext` as pure functions and are applied strictly in slot order by `EffectPipeline`. Record each firing via `ScoreContext.Record(sourceId, description)`; the engine layer animates from that log (no observers/events in Core).
- Tag tests with `[Trait("Category", "...")]` (e.g. `Scoring`, `Determinism`, `Architecture`).
- Expected rule violations return `Result<TValue, TError>` (`PlacementError`, `RoundError`) — exceptions are for programmer errors only.
- Warnings are errors (`Directory.Build.props`). Nullable reference types are on.
